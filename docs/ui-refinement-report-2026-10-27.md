# UI refinement report — 27 October 2026

## Audit and changes

Existing uncommitted copy changes were preserved. Public pages previously loaded together with all admin pages, the original main bundle exceeded 500 kB, logos tried a missing SVG before PNG and were hidden while loading, catalogue controls could expose internal status values, and DB health errors lacked classification. The deployment notes described an earlier preparation phase. No production data or credential changes were made.

The homepage retains its civic identity, headline and search, with shorter spacing and two API-derived cards (MDAs Covered and Services Available) in place of four. Public pilot wording is mapped to Published, Planned or Inactive without changing internal enum values. Catalogue filters based on incomplete paginated results were removed; search and server-side sorting remain, and card heights and links are more compact. The MDA services list precedes official channels; service evidence is closer to fees and conflicting information has an explicit label. Several public pages use tighter spacing. Existing fee calculations and API contracts remain unchanged.

Fourteen source logos were converted to local WebP, resized within 160 × 160 pixels, preserving transparency; NIMC retains its original SVG because raster conversion did not preserve its embedded image; original source URLs are in `research/branding/mda-logo-register.json`. Original files total 1,732,875 bytes; optimized assets total approximately 322 kB. Vite generates fingerprinted asset URLs, explicit image dimensions, async decoding and lazy loading. Unknown and failed images use the existing monogram. Deployment must configure caching; it is not automatically configured by the build.

Route-level lazy imports reduced the main JS chunk from 525.65 kB (137.48 kB gzip) to 296.03 kB (96.89 kB gzip); CSS changed from 33.45 to 33.41 kB. These are chunk sizes, not full page transfer totals. Existing semantics, form labels, focus behavior, and status icons were retained. A local 390 px homepage capture showed no horizontal clipping, but used unavailable local API data. The complete requested visual viewport matrix and populated routes still require browser verification.

Database logs now classify common authentication, database, connection, timeout, schema and permission failures without logging raw errors. Added read-only smoke and DB diagnostic scripts and incident guidance. The backend test suite passed 53/53; backend syntax check, frontend lint and production build passed. A network-enabled read-only production smoke check returned 200 for all five endpoints on 27 October 2026; this checks the currently deployed release, not these uncommitted changes. Browser review, actual cache headers, real-device logo timing and deployed behavior remain release checks. See git diff for the complete list of changes, including pre-existing edits.

## Release acceptance closure

**PASS — keyboard:** automated forward and reverse Tab sequences matched on the homepage, catalogue, NIMC, date-of-birth service, methodology, data sources, about, privacy and admin login. Focus outlines were visible. Keyboard activation covered home and catalogue search, sort, fixture-based Load more, MDA/service and methodology/data-source links, evidence and official-channel links, and admin inputs/password visibility without a login submission. External destinations were intercepted locally.

**PASS — practical semantics:** Chromium accessibility-tree checks found one H1 and named landmarks/controls/links on the reviewed public pages. The catalogue gained an H2 for results, including loading, empty and error states; unnamed decorative admin-login icons were hidden. Loading exposes a status, and controlled empty/error responses presented understandable messages and retry. The existing fallback and status text remain available to assistive technology. This is not specialist screen-reader certification.

**PASS — production-build cache experiment:** using a local server configured with the proposed immutable asset policy, first loads transferred assets; normal reload returned main JS, CSS, homepage chunk, logo module and sampled FCT-IRS/NIMC logos from browser memory cache with zero transferred bytes. SPA revisit did not request the same assets again. Public API requests were repeated on revisit as fresh GETs. No unexpected logo or route-chunk failures appeared. This experiment does not establish production headers.

**HUMAN ACCEPTANCE REQUIRED — actual browser zoom:** Chromium shortcut attempts did not change browser zoom or measurable scale, and a temporary extension test could not expose the browser zoom API. On a local production preview, use the browser's zoom menu to select 125%, 150% and 200% and inspect homepage, catalogue, NIMC and date-of-birth service; check navigation, text, search, fees, evidence and horizontal scrolling, then reset to 100%.

**NON-BLOCKING LIMITATION:** current production HTML uses `no-cache, no-store, must-revalidate`; sampled CSS and legacy logo use seven-day caching; sampled JS has no Cache-Control. Before release, arrange HTML revalidation and one-year immutable caching scoped only to fingerprinted `/assets/` JS, CSS, WebP and SVG; after release verify actual headers and normal navigation in the browser. No production configuration was changed.

A final per-route keyboard activation check also used Enter on a navigation link from each public route and Space on the admin password-visibility button. All nine checks passed. The catalogue results heading remains present in populated, empty, loading and error states. Actual browser zoom remains the sole human acceptance item identified by this review.
